# A1 环境搭建手册：CommunicationMod 跑通 + 规则 Agent 打完一局

目标：游戏由 ModTheSpire 加载 BaseMod + CommunicationMod 启动，外部进程
（`bridge/run_agent.sh` → spirecomm 规则 Agent）接管操作，自动开一局并打完。

## 0. 前置（需人工完成）

- Steam 安装《Slay the Spire》杀戮尖塔1（App ID **646570**）。
  本机已装杀戮尖塔2，两者目录不同，别混淆。
- Java：系统默认 Java 25。ModTheSpire 3.6.3 对新 JDK 兼容性未知，若启动失败
  按 §4 处理。

## 1. Python 侧（已就绪，换机器时重跑）

```bash
cd ~/Codes/cynos/spire-scholar
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt   # spirecomm 来自 vendor/
.venv/bin/python tests/smoke_test.py        # 应输出 "冒烟通过 ✓"
```

## 2. Mod 安装

```bash
bash scripts/setup-mods.sh    # 下载三件套到 game-mods/（已校验完整性）
GAME=~/.local/share/Steam/steamapps/common/Slay\ the\ Spire
mkdir -p "$GAME/Mods"
cp game-mods/ModTheSpire.jar "$GAME/"
cp game-mods/BaseMod.jar game-mods/CommunicationMod.jar "$GAME/Mods/"
```

## 3. 首次启动与 SpireConfig

```bash
cd "$GAME"
java -jar ModTheSpire.jar     # 弹出 mod 勾选窗口
```

- 勾选 **BaseMod** 和 **CommunicationMod**，点 Launch。
- CommunicationMod 首次运行会在游戏目录生成 SpireConfig（properties 格式）。
  找不到就搜：`find "$GAME" -maxdepth 2 -iname "*spireconfig*"`
- 编辑 SpireConfig，写入外部进程命令（注意路径转义）：

```properties
command=/home/sj/Codes/cynos/spire-scholar/bridge/run_agent.sh
```

- `bridge/run_agent.sh` 会自己 cd 回仓库再启动 `.venv/bin/python -m bridge/main.py`，
  默认 `--class ironclad --ascension 0`（随机种子）。要改参数，直接编辑该脚本。

## 4. Java 版本排障

若 `java -jar ModTheSpire.jar` 或游戏本体报错（Class 版本/反射限制等）：

```bash
sudo dnf install java-17-openjdk        # Fedora 系
JAVA_HOME=/usr/lib/jvm/java-17 java -jar ModTheSpire.jar
```

ModTheSpire 3.6.3 时代的主流环境是 Java 8~17，优先试 17，再试 11/8。
游戏本体若自带 JRE 目录也可直接用。

## 5. 验收流程

1. 用 ModTheSpire 启动（勾选两个 mod）。
2. 游戏启动后 CommunicationMod 拉起 bridge 进程；观察仓库
   `logs/run-*.jsonl` 开始写入 `game_start`。
3. Agent 自动 `start` 一局（战士、进阶0）并接管全部操作：
   选卡、路线、战斗出牌、篝火、商店、事件。
4. **A1 验收**：任意一局自动通过第一层（floor ≥ 2，含至少一场战斗）；
   全局日志无 `handle_error` 异常。
5. 若卡死：看游戏目录下 CommunicationMod 日志与 bridge stdout；
   常见原因是 SpireConfig 路径转义错误、脚本无执行权限。

  降级方案是固定 Steam 游戏 beta 分支。
