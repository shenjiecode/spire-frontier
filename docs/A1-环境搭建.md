# A1 环境搭建手册：CommunicationMod 跑通 + 规则 Agent 自动打一局

> 本手册为 2026-09-17 实测打通版本，包含全部踩坑结论。
> 目标：游戏由 ModTheSpire 加载 BaseMod + CommunicationMod 启动，
> bridge（spirecomm 规则 Agent）被自动拉起并接管操作。

## 0. 前置（需人工完成）

- Steam 安装《Slay the Spire》杀戮尖塔1（App ID **646570**）。
  注意目录名是 `SlayTheSpire`（无空格），别和杀戮尖塔2（`Slay the Spire 2`）混淆。
- 游戏本体语言随意（中文可），但 bridge 已对编码做防御；若再遇名字匹配类
  命令被拒，优先怀疑编码（见 §6）。

## 1. Python 侧

```bash
cd ~/Codes/cynos/spire-scholar
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt   # spirecomm 来自 vendor/（本地路径）
.venv/bin/python tests/smoke_test.py        # 应输出 "冒烟通过 ✓"
```

要求 Python ≥3.10（构建 venv 用）；沙盒内 CommunicationMod 拉起时用的是
系统 python3（3.7 也可跑，代码兼容）。

## 2. Mod 安装（关键：目录必须是小写 mods）

```bash
bash scripts/setup-mods.sh    # 下载三件套到 game-mods/（脚本含完整性校验）
GAME=~/.local/share/Steam/steamapps/common/SlayTheSpire
mkdir -p "$GAME/mods"          # ⚠ 小写！Linux 大小写敏感，"Mods" 会导致列表为空
cp game-mods/BaseMod.jar game-mods/CommunicationMod.jar "$GAME/mods/"
cp game-mods/ModTheSpire.jar "$GAME/"
```

版本要求：
- **ModTheSpire ≥ 3.18.1**（GitHub releases 止步 v3.6.3，不满足！
  CommunicationMod 1.2.1 要求 ≥3.18.1。两个来源：
  ① Steam 创意工坊订阅 Mod The Spire（当前 3.30.1，Steam 启动会经
  mts-launcher 自动用上）；② 社区渠道拿 3.30.x 的 jar）
- BaseMod 5.5.0 ✓（要求 mts ≥3.6.0）
- CommunicationMod 1.2.1 ✓

MTS GUI 里 mod 显示红色 = 版本要求不满足，悬停/右侧 Status 看原因。

## 3. 启动方式二选一

### 方式 A：Steam 启动（用了工坊 MTS 时）

Steam 里直接启动游戏，mts-launcher 自动走工坊 MTS 3.30.1，
按 UI 勾选 BaseMod + CommunicationMod → Play。
游戏跑在 Steam pressure-vessel 沙盒内——bridge 由它拉起时用沙盒内的
系统 python3，代码已兼容（vendor 路径 + 编码处理），/home 目录共享。

### 方式 B：命令行启动（本地 MTS 3.30.1 jar）

```bash
cd "$GAME" && nohup ./jre/bin/java -jar ModTheSpire.jar > /tmp/mts.log 2>&1 &
# 游戏自带 jre/（Java 8），系统 Java 太新反而可能不兼容，优先用自带 jre
```

GUI 弹出后勾选两个 mod → Play。

### Windows 注意事项

Windows 的 CommunicationMod 会把 `command` 按空格拆分，仓库路径含空格时不能
直接把 `C:\Users\...\spire-scholar 2\...` 写进去。可使用一个不含空格的包装器，
例如本仓库提供的 `bridge/run_collector.cmd`；包装器内部再切回仓库路径。
如果只需要验证通信并采集游戏状态，先使用被动采集器，不会自动开局或打出卡牌：

```text
command=cmd.exe /c C:\Users\shenj\spire-scholar-collector.cmd
```

其中 `C:\Users\shenj\spire-scholar-collector.cmd` 只需调用仓库里的
`bridge\run_collector.cmd`。若要恢复规则 Agent，把命令改为你自己的无空格包装器，
其内部执行 `python -m bridge.main`。不要把带空格的仓库路径直接作为
CommunicationMod 的命令参数。

## 4. CommunicationMod 配置（关键文件与开关）

配置文件位置（Linux）：`~/.config/ModTheSpire/CommunicationMod/config.properties`
（由 CommMod 首次启动创建；键名可对照源码 CommunicationMod.java 的常量）

```properties
command=/home/sj/Codes/cynos/spire-scholar/bridge/run_agent.sh
runAtGameStart=true
```

- `command`：外部进程；**run_agent.sh 内部会 cd 回仓库再用绝对路径解释器启动，
  勿手动从游戏目录运行**
- `runAtGameStart=true`：⚠ 默认 false！不开则游戏启动不会拉起 bridge
  （游戏内 Mods→CommunicationMod 面板的 Start Process 按钮可手动触发，
  bridge 崩溃修复后点它即可续接，无需重启游戏）
- 其他键：`verbose`、`maxInitializationTimeout`

启动时游戏会短暂挂起等待 bridge 回 `ready`（Python 启动 1~2 秒），正常。

## 5. 验收流程

1. 启动游戏（方式 A/B）。
2. 观察 bridge 进程：`pgrep -af bridge.main`；仓库 `logs/run-*.jsonl` 出现
   `game_start` 后 agent 自动 start 战士进阶0。
3. 全自动：选卡、路线、战斗、商店（购买/删卡）、事件、篝火、Boss 奖励。
4. **A1 验收**：自动通过第一层（floor ≥ 2 且至少一场战斗），
   无未捕获异常；`handle_error` 允许偶发命令被拒后自愈。
5. 卡住排障顺序：
   - `pgrep -af bridge.main` 是否活着 → 死了看下条的错误日志
   - 游戏目录 `communication_mod_errors.log`（bridge 的 stderr 落这里）
   - `/tmp/mts.log`（MTS 侧）
   - `~/.config/ModTheSpire/CommunicationMod/config.properties` 是否被重置

被动采集器运行时，JSONL 会写入仓库 `logs/communication-*.jsonl`。它只能记录
CommunicationMod 暴露的当前局状态（手牌、牌堆、遗物、药水、敌人意图等），不能
一次性导出游戏内全部卡牌、遗物、药水或敌人定义；全量静态数据仍需另写 dump mod
或从游戏资源中提取，再与 Wiki 逐字段核对。

## 6. 已踩坑记录（2026-09-17）

| 坑 | 症状 | 解法 |
|---|---|---|
| mods 目录大小写 | MTS 列表为空、打开目录按钮报 "The file: mods doesn't exist" | 目录必须小写 `mods` |
| MTS 版本过低 | GUI 里 CommunicationMod 标红 | 装 ≥3.18.1（工坊 3.30.1 已验证） |
| runAtGameStart 默认 false | 游戏启动不拉 bridge，无报错 | 配置写 true，或游戏内手动点 Start Process |
| CommMod 读的是 config.properties | 预写其他文件名无效 | 以 SpireConfig("CommunicationMod","config") 为准 |
| 沙盒 python3.7 | venv 的 3.14 不可用 | bridge 代码兼容 3.7+，spirecomm 走 vendor |
| vendor 路径层级 | No module named 'spirecomm.communication' | sys.path 必须指到 vendor/spirecomm（项目根） |
| 中文卡名命令被拒 | `choose ????` Invalid argument | choose 发索引（不发本地化名字）；PYTHONIOENCODING=utf-8 兜底 |
| 命令被拒即崩 | handle_error 默认 raise → bridge 死 → 游戏永久等待 | RuleAgent.handle_error 改为记日志+StateAction 自愈 |

## 7. 已知限制

- vendor 的 spirecomm（2019）无 Watcher 枚举：观者需 A2 自研 mod 补 stance
  后一并升级 spirecomm（matthewReff fork 已支持）再启用
- 商店购买用索引复现了游戏端列表顺序（purge→卡→遗物→药水），
  若 CommunicationMod 更新改动顺序需同步
- 游戏内手动 Start Process 续接的是当前进行中的 run；重启游戏则会开新 run
