# 数据库记录说明

以 `data/spire.sqlite` 为主库；`data/records/*.jsonl` 是面向 Mod、AI 和应用的聚合记录，每行一个 active 实体（`xiaoheihe_articles.jsonl` 单独存来源文章）。`data/exports/` 是关系表导出。现有 Markdown Wiki 可用于人工浏览。图片仅用于临时辅助审核，不作为识别实体或运行知识库的必要条件。

## 分类和身份

记录按 character、card、relic、potion、monster、encounter、event、status、keyword、mechanic 分文件。每条记录的 `categories` 保留小黑盒目录的 category、subcategory、article_id，`xiaoheihe` 保存来源URL、快照时间及关联方式；未匹配的分类不猜测补齐。怪物合页仍以组记录保留，不能把 71 条 monster 记录解释为 71 个独立怪物。

`id` 是本库稳定标识；`game_id` 是游戏内部标识，可能为空。Mod 对接时用 `kind + game_id` 精确匹配，不能只按英文显示名猜测。`name_zh`、`name_en` 是首选名称，`names` 保留别名。卡牌升级通过 `variants` 的 level、variant_kind、condition 表达。候选和废弃实体仍留在 SQLite 中供审核，不进入 active JSONL。

```sh
python -X utf8 scripts/kb/query.py entity "Body Slam" --kind card
python -X utf8 scripts/kb/query.py entity "全身撞击" --kind card
```

查询结果含 `data` 类别字段；卡牌附带基础/升级费用和双语描述，事件附带选项，怪物附带已有动作，遭遇附带成员。SQL 可查询 `entity_records` 视图获得身份、双语首选名和理解，再按 entity_id 联结类别表。

## 理解和来源

`understanding` 允许为空。小黑盒“策略”“小技巧”“应对”“协同效应”等明确建议章节可以填入；只有卡面描述、背景文案或图片时不填。“说明”不自动当作理解。两份独立攻略不参与这个流程。

`entity_understanding` 存理解正文、origin 和 verification_status。自动导入内容标记为 `origin=xiaoheihe`、`verification_status=source_opinion`，表示来源观点，不表示经过规则核验。`understanding_sources` 保存原文摘录、章节定位、source_page_id；聚合记录附带 URL、快照哈希和采集时间。原文可能有排版或文字错误，当前保留摘录，不把猜测改写成规则。

人工编辑理解时将 origin 改为 `manual`，后续构建不会覆盖该正文。源摘录会按已保存的小黑盒快照重建，仍可用来追溯。

## 构建和校验

已有基础库上执行：

```sh
python -X utf8 scripts/kb/build_records.py
python -X utf8 tests/test_kb_records.py
python -X utf8 scripts/kb/validate_kb.py
```

完整重建顺序见根目录 README；在结构化修复之后运行 build_records，它会应用 `schemas/002_understanding.sql`、提取建议、导出记录及报告。该步骤只读已保存快照，不进行网络采集。重建整个基础库前需另外备份人工编辑；保留 manual 的保证仅适用于 build_records。

## 当前覆盖与缺口

本次导出 974 个 active 实体；37 段建议落在 35 个实体：3 个角色、8 个事件、19 个怪物/怪物组、5 个状态。当前识别到的建议章节没有覆盖卡牌、遗物和药水，它们的理解保持 null。这是现有快照和提取规则的结果，不代表网站一定没有其他形式的相关建议。

卡牌的 `variants[].parsed.game_values.values` 含直接确认的 damage、block、magic_number；magic_number的具体含义需结合卡牌描述，不能统一视为抽牌数。584个变体有直接常量，714/722个变体可生成官方描述，369张卡有目标枚举。条件效果、X费用和无限升级仍需单独建模。未确认数值不猜测填充。

全目录对照见 [审核报告](../reports/xiaoheihe-full-review.md)。`xiao_directory` 保存完整分类；`xiao_page_review` 保存895篇文章文本、表格与章节；`xiao_entity_pages` 保存实体对应关系；`xiao_field_checks` 保存当前值与来源值的比较；`xiao_corrections` 保存修正记录。`review_checks` 是实体级查询摘要。文本相同、页面已读取、游戏常量已确认是不同层次的证据，不能互相替代。
